ACTION_DEFS includes some actions with no handler yet (cd, search, quick_jump, invert_selection, visual_line, properties, terminal, sort_reverse, sidebar_focus, command_palette). Their defaults will now be bound to the no-op _ => {} arm, so pressing e.g. / does nothing rather than opening a search prompt. That's the same as before (they never worked), but if you'd rather not burn those keys, trim them from ACTION_DEFS.
The o vs O distinction relies on norm_spec no longer uppercasing single letters. If someone has an existing config written when it did uppercase, their "o" bindings will now be preserved as "o" (good) and their "O" bindings stay "O" (also good) — but their "o" stored as "O" from before will be treated as Shift+O. They'd need to hand-edit the config. Small migration wart.
copy_dir_all's self-check compares dst_canon against src_canon. It handles dst-not-yet-existing by resolving the parent. But if the parent doesn't exist either, we skip the check and let create_dir_all error out normally. Edge case, not a correctness issue.
is_executable_candidate on Windows now only accepts .exe/.scr/.com. If your users expect to pick .bat files, you'll need to special-case them in launch_with to route through cmd /c start "". I intentionally left that out — it's a whole separate behavior and the current Command::new path fails silently, which is worse than not offering the option.
