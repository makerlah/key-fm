🟠 ORANGE — fix before next release
==============================================================
[O-1] Two instances clobber each other's config
      Source:  Bugs.txt #23 (was never fixed)
      File:    config.py — save_config() / load_config()
      Symptom: Run two keyfm windows → the second save wipes
               the first instance's pins / assoc / key bindings
      Cause:   No file locking around read-modify-write
      Fix:     fcntl.flock (POSIX) / msvcrt.locking (Windows)
               around load+save, OR skip if multi-instance is
               not a real use case
      Trigger: if I ever support two windows / run keyfm twice
               myself / user reports lost pins

── Session-5 review (new bugs found in 1.3.0) ────────────────

[F-1]  NEW   %c regex crash in parse_desktop
        Fix:   re.sub(r"%[cC]", lambda _m: name, q)
        Why:   re.sub treats replacement as template → name with
               \B, \1 etc. raised and killed ALL app discovery
        File:  apps.py: parse_desktop()

[F-2]  NEW   Browse… → .txt crash on Windows
        Fix:   if app is None: showerror(...) ; return
        Why:   app_from_file() returns None on Windows for
               non-executables; run() indexed None["argv"]
        File:  ui.py: open_with() → run()

[F-3]  NEW   App Paths values with args mangled
        Fix:   Parse first quoted token, not str(val).strip('"')
        Why:   Registry values are `"path" --args`; strip() only
               removes END quotes, leaves middle quote → isfile
               fails → app silently dropped from Open With
        File:  apps.py: win_apps()

[F-4]  NEW   cwd from Path= not passed through (fixes #10 tail)
        Fix:   launch_with(..., cwd=saved.get("cwd"))
               + save cwd into assoc entry
        Why:   parse_desktop captured Path= but nobody passed it
               to subprocess.Popen; apps ran from wrong cwd
        File:  ui.py: open_file() + open_with() → run()

[F-5]  NEW   flash() never clears (bug since 1.0)
        Fix:   self.root.after(ms, self.update_status) with
               after_cancel() of previous timer
        Why:   ms parameter was ignored; _flash_job field was
               declared but never used. Stale status for hours.
        File:  ui.py: flash()

[F-6]  NEW   _pack_ = 1 on 32-bit Windows
        Fix:   _pack_ = 4 on 32-bit (1 → 4)
        Why:   Windows ABI uses pack(4); struct offsets were
               2 bytes early for the last 3 fields
        Impact: zero (all those fields were 0 in win_recycle)
        Status: fixed anyway, but effectively IGNORED — no
                user will ever hit it. See #36 note.
        File:  trash.py: SHFILEOPSTRUCTW
