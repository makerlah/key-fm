SEVERITY LEGEND
  [CRIT]  Critical — feature is dead or data can be lost
  [HIGH]  High     — visible misbehaviour / wrong result
  [MED]   Medium   — wrong in edge cases
  [LOW]   Low      — cosmetic / minor robustness


--------------------------------------------------------------------------------
[CRIT] 1. Multi-selection ignored by every file operation
--------------------------------------------------------------------------------
Location: main.rs — KeyFmApp::copy_or_cut / paste / delete_selected
Problem : selected_items: Vec<usize> is populated by the lasso, but every
          file op reads only self.selected_item.
          - copy_or_cut -> self.clipboard = vec![item.path.clone()]   (1 path)
          - delete_selected reads only self.selected_item
          - paste consumes self.clipboard which is always length 1
          Worse:  `if ui.input(|i| i.pointer.primary_pressed()) {
                      self.selected_items.clear();
                  }` wipes any multi-selection on every mouse-down, so even
          lasso-built selections are thrown away the moment the user touches
          the mouse again.
Fix     : Add `fn targets(&self) -> Vec<usize>` returning selected_items if
          non-empty else single selected_item. Use it in copy_or_cut,
          delete_selected, and Open. Stop clearing selected_items on every
          primary press (only clear when starting a fresh lasso).


--------------------------------------------------------------------------------
[CRIT] 2. close_tab() corrupts the surviving tab's saved state
--------------------------------------------------------------------------------
Location: main.rs — close_tab / load_tab / save_current_tab
Problem : close_tab removes self.tabs[self.cur_tab] then calls load_tab(idx).
          load_tab starts with save_current_tab(), which writes the *current
          view* (the just-closed tab's cwd/filter/focus) into whichever tab
          now occupies cur_tab, overwriting that tab's saved state.
Fix     : Save the current view BEFORE remove; after remove+clamp, load the
          target tab without triggering save_current_tab (either inline the
          load or add load_tab_no_save(index)).


--------------------------------------------------------------------------------
[CRIT] 3. Current tab label is stale after navigation
--------------------------------------------------------------------------------
Location: main.rs — navigate_to consumer at end of update()
Problem : Navigating updates self.cwd but never the active tab's Tab::cwd, so
          the tab-strip label keeps showing the OLD directory until the user
          switches tabs.
Fix     : After `self.cwd = new_path; self.refresh_dir();`, do
          `if let Some(t) = self.tabs.get_mut(self.cur_tab) {
               t.cwd = Some(std::path::PathBuf::from(&self.cwd));
           }`.
          Do the same anywhere else self.cwd is mutated.


--------------------------------------------------------------------------------
[CRIT] 4. Virtual locations (This PC / Recycle Bin) are dead
--------------------------------------------------------------------------------
Location: main.rs — refresh_dir, sidebar click handler
Problem : Sidebar navigates to "::recycle-bin::" and "::this-pc::", but
          refresh_dir calls std::fs::read_dir on those strings -> Err -> empty
          view, no error surfaced, self.cwd now points at a fake path.
          Recycle Bin is only pushed by drives::known_folders on Windows;
          THIS_PC is defined but never used anywhere.
Fix     : In refresh_dir, branch on self.cwd:
          - THIS_PC    -> populate from drives::scan_drives()
          - RECYCLE    -> populate from $Recycle.Bin\<sid>\$I* files via
                          trash::parse_i_file (extend it to return the
                          original path); non-Windows -> status_msg.
          Add a sidebar button for This PC. Guard Path::parent() and Back/Up
          when constants::VIRTUAL contains self.cwd.


--------------------------------------------------------------------------------
[CRIT] 5. F2 conflict — dark-mode toggle unreachable, Rename on reserved key
--------------------------------------------------------------------------------
Location: keys.rs (FIXED_KEYS, ACTION_DEFS toggle_dark) + main.rs keyboard
Problem : F2 is reserved (FIXED_KEYS) and bound to toggle_dark in ACTION_DEFS,
          but the main.rs hardcoded keyboard block uses F2 to open the Rename
          dialog. So toggle_dark can never fire, and Rename sits on a
          "reserved" key. config.dark can only be changed by editing the file.
Fix     : Remove ("F2","toggle_dark") from FIXED_KEYS, change toggle_dark's
          default_keys to &["Ctrl+Shift+d"], remove the F2->Rename branch in
          main.rs, add:
            if ctx.input(|i| i.modifiers.ctrl && i.modifiers.shift
                            && i.key_pressed(egui::Key::D)) {
                self.config.dark = !self.config.dark;
                self.theme = if self.config.dark { DARK } else { LIGHT };
                let _ = keyfm::config::save_config(&self.config);
            }


--------------------------------------------------------------------------------
[CRIT] 6. config.keys / config.unpinned / config.assoc are dead features
--------------------------------------------------------------------------------
Location: main.rs keyboard dispatch vs. config.rs + keys.rs
Problem : config.rs carefully parses user key bindings into cfg.keys, keys.rs
          provides the full action table (ACTION_DEFS), and main.rs dispatches
          keys via hardcoded egui::Key::* checks only. None of these actions
          are implemented at all:
            up/down, page_up/page_down, home/end, parent, root, recycle, cd,
            search, quick_jump, select, select_all, invert_selection,
            clear_selection, visual_line, copy, cut, paste, delete,
            permanent_delete, rename, new_file, new_dir, properties,
            open_default, open_with, terminal, toggle_hidden, toggle_dark,
            sort_*, pin, sidebar_focus, help, refresh (only F5), quit,
            command_palette.
          config.assoc ("Open With" associations) is parsed but never used.
          config.unpinned is parsed but never used.
Fix     : Build a resolved binding map at startup (user config overrides
          defaults) and dispatch through it. Stub the actions whose behaviour
          is missing.


--------------------------------------------------------------------------------
[CRIT] 7. Old pin file is deleted before the new config is saved
--------------------------------------------------------------------------------
Location: config.rs — load_config_from
Problem : When the main config is missing/corrupt and the old pin file
          exists, cfg.pins is filled from old_pins and then
          fs::remove_file(old_pins) runs immediately. Nothing calls
          save_config() unless the user happens to pin/unpin. Quitting
          afterwards = pins gone forever.
Fix     : Do NOT remove old_pins inside load_config_from. Either return
          (Config, needs_save: bool) and have KeyFmApp::new call save_config
          when true, or defer the remove to save_config_to after a successful
          save. Only delete old_pins on success.

[HIGH] 10. Cut clipboard is wiped even on partial failure
--------------------------------------------------------------------------------
Location: main.rs — paste
Problem : `if self.clip_mode == "cut" { self.clipboard.clear(); }` runs

--------------------------------------------------------------------------------
[HIGH] 11. Back / Forward buttons are wrong
--------------------------------------------------------------------------------
Location: main.rs — toolbar
Problem : "Back" calls Path::parent (identical to "Up", not history).
          "Forward" is a no-op (`// Forward navigation placeholder`).
          Tab.back / Tab.fwd are stored but never used.
Fix     : Use Tab.back / Tab.fwd as a real history stack. Push old cwd on
          navigate; clear fwd. Back pops from back -> push to fwd -> set cwd.
          Forward pops from fwd -> push to back -> set cwd.


--------------------------------------------------------------------------------
[HIGH] 12. Delete failure deselects and hides the error
--------------------------------------------------------------------------------
Location: main.rs — delete_selected
Problem : self.selected_item = None runs inside the if-let before knowing
          whether the delete succeeded; on Err, status_msg is set but the
          item stays and the user has to re-find it.
Fix     : Capture Result, set selected_item = None only on Ok, set
          status_msg on Err, keep the selection so the user can retry.


--------------------------------------------------------------------------------
[HIGH] 13. navigate_to accepts arbitrary strings; ~ is not expanded
--------------------------------------------------------------------------------
Location: main.rs — path-input Enter handler and end-of-update
Problem : Typing "~/Downloads" does not expand the tilde (only
          helpers::get_start_dir does, via shellexpand_tilde). Invalid paths
          silently leave an empty view with garbage self.cwd and no message.
Fix     : Add helpers::expand_and_validate(&str) -> Option<PathBuf> that
          expands a leading ~, resolves absolute, and checks is_dir(). Use it
          in the path input handler and at the navigate_to consumer. On None,
          set self.status_msg = "Not a directory: <raw>".


--------------------------------------------------------------------------------
[MED] 14. Post-create / post-rename reselect picks wrong entry
--------------------------------------------------------------------------------
Location: main.rs — active_dialog handling
Problem : After success, `self.entries.iter().position(|it| it.name == name)`
          matches by name only. If two entries share a name (or File::create
          overwrote an existing file), the wrong index is selected.
Fix     : Match on item.path == base.join(&name). Also check
          base.join(&name).exists() before File::create / create_dir and
          surface "Already exists" while keeping the dialog open.


--------------------------------------------------------------------------------
[MED] 15. norm_spec does not case-fold non-letter keys
--------------------------------------------------------------------------------
Location: keys.rs — norm_spec
Problem : Only single alphabetic characters are uppercased. So "esc" stays
          "esc" while "Escape" -> "Esc". "tab"/"Tab" behave inconsistently.
          Case-insensitive intent is not realised.
Fix     : Lowercase keys in get_key_aliases / get_key_display; lowercase
          lookup_key before map lookups. Add unit tests:
            norm_spec("esc")   == norm_spec("Escape") == "Esc"
            norm_spec("ctrl+return") == "Ctrl+Enter"


--------------------------------------------------------------------------------
[MED] 16. '+' itself is unbindable in split_key
--------------------------------------------------------------------------------
Location: keys.rs — split_key
Problem : spec.split('+') drops the empty segment, so "Ctrl++" -> ["Ctrl"]
          and "+" -> [].
Fix     : Special-case trailing "++" / bare "+". Test:
            split_key("Ctrl++") == (["Ctrl"], "+")

[MED] 17. Keyboard navigation ignores the filter
--------------------------------------------------------------------------------
Location: main.rs — arrow-key handlers

Fix     : Add fn visible_indices(&self) -> Vec<usize>; move selection
          within that list and map back to entries indices. Reset

[LOW] 26. Lasso/single-selection interleaving destroys "last-touched" meaning
--------------------------------------------------------------------------------
Location: main.rs — lasso render loop
Problem : Inside the lasso branch, `self.selected_item = Some(idx)` is
          executed for every row the lasso touches, so the final
          selected_item is the last touched row — which then becomes the
          single target of file ops that read selected_item.
Fix     : Remove the assignment from inside the loop. On primary release,
          set self.selected_item = selected_items.last().copied() if
          non-empty, or rely on targets() preferring selected_items.

[HIGH] 41. Lasso drag triggers ScrollArea drag-to-scroll
--------------------------------------------------------------------------------
Location: main.rs — egui::ScrollArea in CentralPanel
Problem : ScrollArea defaults to drag_to_scroll(true). Dragging inside the
          list while lassoing is interpreted as a scroll gesture, so the
          viewport scrolls (and appears to "move down" when the user drags
          up) while the lasso rectangle is drawn. Reported after fixing
          bug 1: dragging up causes the screen to scroll down.
Fix     : Change the ScrollArea builder to:
            egui::ScrollArea::vertical()
                .auto_shrink([false, false])
                .drag_to_scroll(false)
                .show(ui, |ui| { ... })
          Also change the remaining_rect interaction from Sense::click() to
          Sense::click_and_drag() so a lasso started below the last row still
          extends selected_items. Wheel scrolling continues to work
          independently of drag_to_scroll.
